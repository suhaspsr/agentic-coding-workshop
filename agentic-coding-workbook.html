Before the session

  • Have Python 3.10–3.12 (3.11 or 3.12 recommended), Git, and a signed-in Copilot client with local execution available. Poetry is optional; the README explains both setup options.
  • Get the approved internal marketplace URL and expected plugin release from the presenter, and install it in your client before the timer starts.
  • Clone the starter repository, create your own local branch, and open the repository root in your client. Keep the prepared dependency files and data.
  • Before the timer: create the root .venv using either Poetry or pip, following the README. Verify pandas, scikit-learn and the starter data. Use the same setup throughout.
The core exercise uses the supplied dependency files and needs no Docker, database, cloud account, API key or real customer data. Poetry is optional. Use the root .venv for the whole project.

What the framework takes care of

You describe the task. Orca resolves context, selects relevant methods, runs checks and coordinates required independent review with Titan. You do not need agent or skill names in each prompt.

Bundled skills: orca-skills-first, karpathy-guidelines, find-skills, requirements-discovery, debugging and audit-toolkit. Structured discovery applies to larger or critical work. The audit-toolkit entry needs a separately approved full toolkit; this workshop does not use it. No MCP servers or hooks are bundled.

Required reviews happen during implementation too. If Titan or a required check is unavailable, review or validation remains incomplete. A reported skill name alone is not execution evidence; inspect available work/review records when needed.

Show the selected agent and installed components once. The source used to prepare this workbook declares version 2.0.0; follow the support owner’s approved release on demo day. Never substitute an invented internal URL.

Interpreter setup, if you need it

macOS / Linux

poetry env use python3.11
poetry install --no-root
.venv/bin/python -c "import sys; print(sys.executable)"

Windows PowerShell

poetry env use C:\Path\To\Python311\python.exe
poetry install --no-root
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable)"

Replace the Windows example path with an installed Python 3.10–3.12 executable. Direct interpreter paths work without activating the environment. Without Poetry, follow the pip setup in the README. In the Copilot app, ask the agent to use the root .venv interpreter; with an activated pip environment, use python commands. If Python is absent, use your company’s approved installation process before continuing.

VS Code: run Python: Select Interpreter from the Command Palette and choose the project’s .venv. This needs the approved Python extension. If it is not listed, enter its interpreter path.

Copilot app: ask the agent to use the root .venv interpreter for all commands. Use poetry run python with Poetry or python with the activated pip environment.

Use the commands the agent creates for your project. Ask “Show me the exact command to run that” if you want to run it yourself.

Alternative testing prompts
A useful test checks behavior: invalid input is rejected, a known calculation is correct, or a saved model accepts valid new rows. Ask to see the command, test names and results.
07 / Maintenance
22–25 min

Change one requirement.

Ask for one small addition and check that earlier behavior still works.

Other change requests
If you encounter a real error

Paste the actual traceback or output, the command and what you expected. Use this instead of adding a feature while the program is broken.

No need to introduce a bug deliberately. If it works, continue with the requirement change.

08 / Review & delivery
25–30 min

Make it easy for the next person.

Check before finishing: README commands match the files and interpreter. Review status and blockers are explicit. Run an example command from the README and inspect the result. A draft PR description is ready to copy; nothing needs to be pushed or deployed.
Other handover options
This explicit review request does not replace earlier required reviews. Use review waiting time for questions, and report unfinished reviews as pending. Finish with the original goal, running result, checks and limitations. Publishing a PR, merging and deployment are separate actions.
